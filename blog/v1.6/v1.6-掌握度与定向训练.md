# 掌握度量化与定向训练：让「练什么」由数据决定

> 版本：v1.6 ｜ 主题：学习分析与自适应练习 ｜ 关键词：指数遗忘曲线、置信度收缩、贝叶斯先验、软约束、降级设计

## 1. 背景：随机组卷的两个浪费

前三版把训练闭环搭完之后，做题链路是「随机组卷」：从题库随机抽题。这有两个隐性浪费：

1. **对已掌握的内容重复消耗时间**——你已经会的知识点，随机卷照样往里塞；
2. **对薄弱点覆盖不足**——真正不会的部分，被均摊在随机抽样里，练不到痛点。

解决它需要一个前提：系统能回答「哪里不会」。这个版本做的事情就是把这句话从形容词变成数字，再把这个数字变成一张卷子。

## 2. 知识点一：没有观测数据时，指标应该显示什么

做学习分析最容易踩的坑：**把「没练过」显示成「完全不会」**。

一道题从没做过，正确率是 0/0。如果实现时随手写了「无数据记 0」，用户会看到一片刺眼的 0% 红色，然后对整个仪表盘失去信任——因为他知道自己不是不会，是没做过。

更隐蔽的对称错误是「只做过 1 题且答对」就显示 100%。一次观测的方差大到没有任何结论意义。

工程上成熟的处理是**收缩（shrinkage）**：样本不足时，把观测值向一个中性先验收缩。

```
conf    = min(1, Σw / W_full)        # 置信度：等效观测次数越多越接近 1
mastery = 0.5 + (raw - 0.5) × conf   # 无数据时精确等于 0.5（中性）
```

这个形式本质上是贝叶斯估计里「先验 + 数据」的最简版：先验是 0.5（不知道就是五五开），每多一次观测，就往真实表现方向挪一步。好处有两个：

- 前端可以放心把分数画出来，**同时把置信度也暴露出来**——「42% (置信度 35%)」和「42% (置信度 100%)」是两个完全不同的结论；
- 薄弱判定可以顺手复用置信度：置信度不足的维度根本不参与排名，避免给用户推荐一堆「没练过」的东西让他练。

**教训**：做任何统计指标，先问一句「零观测时它显示什么」。这个问题没有答案，指标就是半成品。

## 3. 知识点二：近期表现应该更值钱——指数遗忘曲线

一个月前做对的题和今天做对的题，对「现在掌握程度」的贡献不应该一样。学习的本质是对抗遗忘，评测也该如此。

用指数衰减实现「近期观测权重更高」：

```
w_i = 0.5 ** (Δdays_i / 14)          # 半衰期 14 天
```

参数选择的依据：半衰期太短（比如 3 天），练过一次的东西几天后就「失忆」，指标会抖得厉害；太长（比如 60 天）则复习带来的进步几乎不反映在分数上。14 天正好横跨两轮 SM-2 复习间隔（1 天 → 6 天 → 15 天），意味着「认真复习过的知识点」在指标上是保值的——这和系统里已有的间隔重复算法是同一套时间观，两套机制互相自洽。

实现上有个容易忽略的细节：**衰减要作用在每条观测上，而不是聚合结果上**。如果先算总正确率再整体打折，「很久没练但全对」和「一直没练」会被混为一谈；逐条加权后，前者是高分（历史表现仍然优秀，只是稍微降温），后者是中性 0.5。

## 4. 知识点三：薄弱判定的双条件

「掌握度低于阈值」不能单独作为推荐依据，否则会闹出这种笑话：用户只做过 1 道填空题且答错 → 填空掌握度 42% → 系统大力推荐「练填空」。而这道题他可能只是手滑。

所以判定必须同时满足：

1. **分数条件**：mastery < 阈值（默认 0.6）
2. **样本条件**：累计权重 ≥ 1.5（约等于近期做过 2 题）
3. **可行动条件**：该维度下还有题可练（组不出卷的推荐没有意义）

第三条容易被忽略。推荐系统的输出不是「结论」而是「行动」，任何不能转化为行动的推荐都只是噪音。这个判断在实测里真的拦住了一个 bug——见第 6 节。

## 5. 知识点四：占比上限是软约束，不是硬约束

定向组卷的策略是分池抽取：错题本未掌握的题优先，但占比不超过 60%（防止「定向练习」退化成「错题重刷」），然后是没做过的题，最后用其余题补足。

第一版实现直接按上限截断。单元测试全过——因为测试数据里各池都有富余。但 E2E 用真实数据跑的时候炸了：

```
该维度下可用题目仅 15 道（其中可组 6 道），请减少数量或放宽条件
```

场景：某个维度的题目**几乎全部都在错题本里**（恰恰是最需要定向练习的场景！）。此时：

- 错题池：15 道，按 60% 上限只取 6 道
- 未作答池：0 道（全都做过了）
- 其余池：0 道（全在错题本里）
- 结果：10 题的卷子只组出 6 道，直接报错

问题出在把「错题占比 ≤ 60%」当成了硬约束。它其实是个**偏好**：目的是「别只刷旧题」，但当不存在「新题」可练时，这个偏好和「组满卷子」的目标冲突了。约束冲突时，**可满足性优先于偏好**——用户要的是一张 10 题的卷子，而不是一个精确的错题比例。

修复：先按上限取，取不满时解除上限补齐。

```
take(pool_wrong, cap_60%)   # 先守偏好
take(pool_fresh, count)     # 再补新题
take(pool_rest, count)      # 再补其余
if 取不满: take(pool_wrong, count)   # 解除上限，宁可多练错题也不组不出卷
```

**教训**：写「占比 / 上限 / 配额」类逻辑时，永远追问一句——当所有候选都来自被限制的那一池时，系统应该报错还是降级？答案是几乎总是降级。

## 6. 知识点五：增强功能不能拖垮核心链路

这个版本还把 v1.5 的混合检索接进了出题链路：出题时可以填一个「知识点聚焦」，系统用混合检索挑出最相关的知识块作为素材，替代原来的「整篇资料所有块随机取」。

但出题是系统的核心链路，检索依赖向量库和 Embedding，属于「可能坏」的组件。设计原则是：**增强失败必须回退，而不是失败**。

```python
try:
    hits = retrieve(db, user_id, focus, top_k, mode="hybrid")
except Exception:
    return []            # 静默回退，调用方走「整篇资料」的老路
```

同时让回退**可见**：响应里带一个取材回执（是否用了检索、命中了几个块），前端把「本次取材经混合检索聚焦，命中 3 个知识块」展示出来。降级不能是静默的黑洞，否则用户填了聚焦词却永远不知道它有没有生效——那这个功能等于没做。

## 7. 测试策略：为什么 E2E 这次抓住了单测抓不住的 bug

上一节的占比 bug 很有代表性：**24 个单元测试全绿，E2E 第一步真实点击就炸**。

原因不是单测没写，而是单测的造数太「理想」：每类池子都有数据，偏好约束总能同时满足。真实用户数据的分布是极端的——错题本里塞满了同一个维度的所有题。

这决定了两级测试的分工：

- **单测**验证规则的正确性（衰减公式对不对、收缩方向对不对、优先级顺序对不对）——造「干净」的数据；
- **E2E** 验证规则在真实数据分布下不崩溃——走真实按钮、真实库、真实时序。

发现 bug 后的补测也遵循同一原则：新单测 `test_targeted_fills_up_when_all_in_wrong_book` 专门构造「4 道题全部在错题本」的极端分布。**修一个 bug 的完整定义是：修掉它，并且加一个只有它才能触发失败的测试。**

## 8. 经验清单

1. 统计指标先回答「零观测显示什么」，答案几乎总是「向中性先验收缩 + 暴露置信度」。
2. 时间衰减逐条观测加权，不要聚合后打折；半衰期参数要和系统里其他时间机制自洽。
3. 推荐系统的输出是行动，不能转化为行动的推荐（无题可练的薄弱项）直接过滤。
4. 占比/配额是软约束，可满足性优先；写约束时先想清楚冲突时的降级路径。
5. 增强功能挂在核心链路上必须可回退，且回退要可见（回执/标记），不能静默黑洞。
6. 单测测规则的正确性，E2E 测真实分布的生存性；bug 修复要配一个专属失败测试。
