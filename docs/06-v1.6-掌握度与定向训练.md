# v1.6 掌握度与定向训练

> 版本：v1.6 | 日期：2026-10-25 | 状态：已交付
> 前置：v1.5 混合检索与检索评测（BM25 + RRF + 查询改写 + 评测集）

## 1. 目标与动机

前五版解决了「录得进 → 出得来 → 考得动 → 讲得清 → 找得准」，但**练什么**仍由用户拍脑袋：
随机组卷对已经掌握的知识点重复消耗时间，对薄弱点又覆盖不足。

v1.6 补上闭环的最后一环——**用历史作答数据量化「哪里不会」，并一键把薄弱点变成一张卷子**：

| 能力 | 说明 |
|---|---|
| 知识点掌握度 | 按资料 / 题型 / 难度三个维度聚合，输出可解释的掌握度分数 |
| 掌握度雷达 | 题型 3 轴 + 难度 3 轴，一眼看出能力形状 |
| 薄弱项识别 | 掌握度低于阈值且样本足够的维度，按升序给出 |
| 针对性练习 | 从薄弱维度一键组卷，优先错题本未掌握题 |
| 出题取材增强 | 出题时用 v1.5 的混合检索聚焦知识点，替代「整篇资料所有块」 |

## 2. 掌握度算法设计

### 2.1 观测来源

一次观测 = 一条已提交会话中的作答记录（`exam_answers` + `exam_sessions.status = submitted`）：

- `correct_i ∈ {0,1}`：是否答对
- `rate_i = score_i / max_score_i`：得分率（含部分正确，比二值更细腻）
- `t_i`：作答时间

通过 `questions` 关联出三个维度键：`q_type`、`difficulty`、`entry_id`。

### 2.2 时间衰减

近期表现比历史表现更能代表当前水平，用**半衰期 14 天**的指数衰减加权：

```
w_i = 0.5 ** (Δdays_i / 14)
```

半衰期取 14 天是权衡：太短（3 天）会让只练过一次的知识点迅速"失忆"，
太长（60 天）则无法反映复习后的进步。14 天约等于两轮 SM-2 复习间隔（1 天 → 6 天 → 15 天）。

### 2.3 加权正确率与置信度收缩

```
acc_w  = Σ w_i·correct_i / Σ w_i
rate_w = Σ w_i·rate_i     / Σ w_i
raw    = 0.7·acc_w + 0.3·rate_w          # 二值正确率为主，得分率补充
conf   = min(1, Σw_i / 5)                # 5 次等效观测达到满置信
mastery = 0.5 + (raw - 0.5)·conf
```

**为什么用 0.5 做收缩基线**：没有观测数据的维度，正确率是 0/0。
直接展示 0% 会把"没练过"误读成"完全不会"，直接展示 100% 更荒谬。
收缩到 0.5（中性）并同时返回 `confidence`，前端可以明确标注"样本不足"，
样本越充分分数越接近真实表现——这是小样本场景下最稳妥的处理。

### 2.4 薄弱判定

```
mastery < threshold（默认 0.6） 且  Σw ≥ 1.5（约 2 次近期作答）
```

两个条件缺一不可：只看分数会把"只做过 1 题且答错"的维度误判为薄弱；
只看样本量则失去意义。同时输出 `wrong_pending`（该维度下仍在错题本中的题数）作为交叉验证信号。

## 3. 针对性练习组卷策略

按优先级分池抽取，保证"薄弱优先、但不只练旧题"：

| 池 | 内容 | 占比上限 |
|---|---|---|
| A | 该维度下 approved 且在错题本中未掌握（SM-2 `repetitions < 3`）的题 | 60% |
| B | 该维度下 approved 且**从未作答**的题 | 不限 |
| C | 该维度下 approved 的其余题 | 补足 |

顺序 A → B → C 随机抽取并去重，取满 `count`。
可用题不足时**明确报 400 并给出实际数量**，不静默凑数（与随机组卷一致的口径）。

试卷 `config` 写入 `{"mode": "targeted", "dim": ..., "key": ...}`，
标题形如 `针对性练习 · 单选（掌握度 42%）`，便于后续按 mode 统计定向练习的提分效果。

## 4. 出题链路接入混合检索

**改造前**：`POST /questions/generate` 取「指定资料的所有块」或「全库所有块」，随机挑块出题。
资料一大，出题分布就发散，且无法针对某个知识点出题。

**改造后**：新增可选参数 `focus`（知识点/主题描述）与 `retrieval_top_k`：

1. 传入 `focus` → 调用 v1.5 的 `retrieval.retrieve(mode="hybrid")` 得到 top-k 相关块；
2. 若同时指定 `entry_id`，在检索结果内按 entry 过滤（检索本身按用户全库召回，过滤在内存做）；
3. 检索无结果 / 抛异常 → **回退**到原逻辑（整篇资料块），并在响应里标记 `retrieval.used=false`；
4. 响应新增 `retrieval: {used, focus, mode, hit_count, chunk_ids}`，前端可展示"本次取材命中 N 个知识块"。

回退设计的原因：检索依赖向量库与 Embedding 可用性，出题是核心链路，不能因为检索失败就整体失败。

## 8. 风险与边界

| 风险 | 处理 |
|---|---|
| 样本极少时掌握度不可信 | 0.5 收缩 + `confidence` 显式暴露 + 薄弱判定要求 Σw ≥ 1.5 |
| 定向练习题库不足 | 明确 400 报数，不静默凑数 |
| 检索失败拖垮出题 | 回退到原整篇取材，响应标记 |
| 维度标签硬编码 | 题型/难度走常量表，资料维度取真实标题；无资料题归入"未关联资料" |

| 验证项 | 结果 |
|---|---|
| `pytest` 单元测试 | **140 passed**（新增掌握度 24：衰减/收缩/三维聚合/薄弱判定/定向取材） |
| API 冒烟测试 | **116/116 通过**（新增 §7.7 共 23 项断言） |
| 浏览器 E2E | **15/15 通过**（新增第 15 步：掌握度页雷达 + 维度表 + 真实点击「一键练习」组卷并进入考试页） |
| `tsc --noEmit` + `vite build` | 通过（21.6s） |

**demo 种子数据上的实测读数**（2 场种子考试 + 多轮 E2E 累积作答，206~220 次观测）：

| 指标 | 数值 | 说明 |
|---|---|---|
| 综合掌握度 | 10% | 种子考生的随机作答，符合预期 |
| 薄弱维度 | 5 个 | 「题型-填空 4%」「资料-MySQL 索引与事务 7%」「难度-中等 9%」等 |
| 雷达 6 轴 | 全部有值 | 未观测维度显示中性 50% |
| 定向组卷 | 掌握度 4% → 10 题填空卷 | 标题带掌握度，`config.mode=targeted` |
| 出题聚焦 | `focus="ETag 协商缓存"` → 命中 3 块 | 未聚焦时回执 `used=false`（全篇取材） |

**过程中发现并修复的真实缺陷**：

1. **错题占比上限导致组不满卷**：某维度题目几乎全在错题本时（demo 用户填空题 15 道全部待消化），
   60% 上限使 10 题的卷子只能组出 6 道。E2E 用真实按钮走「薄弱项 → 一键练习 → 组卷」才暴露——
   纯 API 单测因为数据分布太理想测不出来。修复：取不满时解除占比上限补齐，并补专门单测。
2. **「未关联资料」伪维度**：`entry_id` 为空的题目在资料维度形成一个 key=None 的维度项，
   会让响应模型校验失败，且可能被推荐成薄弱项。修复：键归一化为 0，薄弱推荐跳过，定向取材支持 `IS NULL`。
