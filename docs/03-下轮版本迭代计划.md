## 2. 下轮方案（三选一）

### 方案 X：AI 应用纵深（推荐）

求职方向是 AI 应用全栈，此轮直接加码"AI 工程能力"证据链，且 v1.5 的**检索评测集**是同质化 RAG 项目中最稀缺的差异化素材。

| 版本 | 主题 | 内容 |
|---|---|---|
| v1.4 | 对话式讲题 | 错题/结果页「问 AI」侧边窗；上下文工程（题干+标准答案+考生答案+解析+资料原文）；SSE 流式输出；对话历史按题目归档；无 Key 入口禁用并引导配置 |
| v1.5 | RAG 检索增强与评测 | 出题素材检索升级混合检索（向量 + BM25）+ RRF 融合；查询改写；**构建 10~20 组检索评测集（查询→期望块），量化 Recall@5 提升**；检索质量报告页 |
| v1.6 | 掌握度与定向训练 | 知识点掌握度雷达（按资料/题型/难度多维）；「针对性练习」一键从薄弱维度组卷；出题时优先检索薄弱相关知识块 |

**亮点**：评测集 + 前后量化对比，把"感觉更快了"变成"Recall@5 从 0.62 → 0.85"。**风险**：核心功能需 API Key（讲题/检索增强），需做好降级与演示模式说明。

### 方案 Y：工程化与部署

补齐"能上线"叙事，适合简历缺工程证据的场景。

| 版本 | 主题 | 内容 |
|---|---|---|
| v1.4 | PostgreSQL + pgvector | `DATABASE_URL` 切 PG；pgvector 替代 ChromaDB（vector_store 已封装，工作量集中在迁移脚本与向量 SQL）；alembic 版本化迁移（替代 create_all）；SQLite→PG 数据迁移脚本 |
| v1.5 | Docker Compose | backend + frontend(nginx) + postgres + 向量库四件套；一键 `docker compose up`；健康检查与依赖编排；生产构建优化 |
| v1.6 | CI/CD | GitHub Actions：lint + 单测 + 构建 + 镜像；PR 检查；Release 流水线 |

**亮点**：上线叙事完整。**注意**：用户可感知的功能增量少。

### 方案 Z：数据产品化（轻量）

自己立刻受益，节奏快。

| 版本 | 主题 | 内容 |
|---|---|---|
| v1.4 | 导出与周报 | 题库/错题本导出 Anki（TSV）与 Markdown；每周学习报告（练习量、正确率、错题消化数） |
| v1.5 | 考试体验 | 答题卡导航（跳题/已答标识）、可选倒计时自动提交、成绩单 PDF 导出 |

## 7. v1.4 设计摘要（决策后展开）

**目标**：错题/考试结果页可对任意题目发起「问 AI」多轮对话讲解。

- 后端：新表 `ai_chat_sessions`（按题目归档）+ `ai_chat_messages`；SSE 流式输出（`text/event-stream`，逐 chunk 转发）；上下文组装 = 题干 + 选项 + 标准答案 + 解析 + 考生最近答案 + 关联资料原文（RAG 检索 top-3）
- 提示词工程：系统提示限定"基于给定资料讲解，不编造"；注入题目 JSON 与资料块
- 降级：未配置 Key 时入口禁用 + 引导去系统配置页；LLM 调用失败返回可重试错误
- 前端：结果页/错题本「问 AI」按钮 → 右侧抽屉对话窗（消息列表 + 输入框 + 流式渲染）；历史会话按题目恢复
- 验证：SSE 单测（mock LLM 流）、冒烟（创建会话/发送/历史）、E2E（需 Key，至少验证入口态与降级提示）
