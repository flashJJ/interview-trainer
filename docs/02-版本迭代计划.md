## 1. 背景与迭代目标

v1.0 已形成完整训练闭环。下一阶段的三个迭代目标：

1. **产品闭环深化**：从"练完就结束"进阶到"错题有人管、复习有节奏"（留存价值）
2. **求职叙事强化**：每个版本产出可写进简历的硬素材（算法 / 人机协同 / 工程化）
3. **演示可行性**：新功能在无 LLM Key 的演示模式下必须可用（不把核心功能绑死在 API 上）

### 约束
- 单用户演示系统，不引入重依赖（不上消息队列 / 微服务）
- 每个版本必须：单测 + 冒烟 + E2E 三级验证通过、文档同步、可演示

## 3. 方案 A（推荐）：训练闭环深化

### v1.1 错题本与间隔重复（SM-2）

**目标**：让错题自动进入复习队列，按遗忘曲线安排复习节奏。

**功能清单**
- 错题自动收集：提交后 `score < 60% × max_score` 的题进入错题本（已有 exam_answers 数据，零新增采集）
- 错题本页面：列表（按错误次数/最近错误排序）、筛选（题型/来源资料）、错误次数徽标
- SM-2 间隔重复算法：每道错题维护 `easiness / interval / repetitions / due_date`，复习答对升档、答错降档，到期提醒
- 「今日待复习」入口 + 复习模式（只练到期错题，练完更新排期）
- 做题分析看板增加：错题总数、今日待复习数、7 日复习计划

**技术要点**：新增 `wrong_questions` 表（question_id/user_id/error_count/sm2 字段）；SM-2 为标准算法（约 60 行纯函数，可单测）；复习会话复用 exam_sessions（type=review）。

**验收标准**：错题本正确收录（含边界：半分题是否算错→定义为算）；SM-2 单测覆盖升降档；E2E 走通"考试产生错题→错题本可见→复习→排期更新"。

**预估**：4-5 人天。

### v1.2 出题审核流（人机协同）

**目标**：AI 生成的题目先过人工审，质量可控，同时这是"人机协同工作流"的面试好素材。

**功能清单**
- Question 增加 `review_status`（pending / approved / rejected），LLM/规则生成的题默认 pending
- 「题目审核」页面：待审队列（按资料/题型分组）、通过/拒绝/**编辑后通过**（模态框改题干/选项/答案/解析）
- 题库默认只显示 approved；组卷只从 approved 抽题（避免烂题进考卷）
- 批量操作：整份资料一键通过/按资料批量通过
- 统计：审核通过率、各资料待审数

**技术要点**：题库筛选逻辑加状态条件；审核页复用题库表格组件；编辑走现有 Question 模型（无 schema 变更）。

**验收标准**：未审核题不出现在组卷池；编辑后题目内容与答案一致性校验（选择题答案字母须在选项内）；E2E 走通"出题→审核通过→组卷可见"。

**预估**：3-4 人天。

### v1.3 资料导入扩展

**目标**：覆盖真实资料形态（PDF 笔记 / Word 文档 / 网页文章）。

**功能清单**
- 上传支持 `.pdf`（pypdf 提取文本）、`.docx`（python-docx）、`.md/.txt`（已有）
- URL 录入：输入网页链接，后端抓取正文（trafilatura 或 readability-lxml 提取正文，去广告导航）
- 大文档处理：>5MB 或超长文档给出明确提示；导入后走现有处理流水线
- 资料类型标签与筛选

**技术要点**：正文提取库二选一（trafilatura 效果好但依赖重 / readability-lxml 轻量）；文件大小与页数上限；PDF 扫描件无文本层时明确报错（不做 OCR）。

**验收标准**：三种格式各 1 个真实文件测试导入→分块→出题；URL 导入对 2-3 个技术博客页面验证正文提取率；失败场景（扫描 PDF/需登录页面）有友好错误。

**预估**：4-5 人天。

### 方案 A 交付物
- 3 个版本分支 → develop → main 合并（每个版本一个 tag：v1.1 / v1.2 / v1.3）
- 简历素材：SM-2 间隔重复算法落地、人机协同审核流、多格式文档解析管线

## 4. 方案 B：AI 能力纵深

### v1.1 对话式讲题
- 错题/结果页「问 AI」按钮 → 侧边对话窗：上下文携带题目、标准答案、考生答案、解析
- 多轮追问、流式输出（SSE）、对话历史按题目归档
- 无 Key 时入口禁用并提示去配置

### v1.2 RAG 检索增强
- 出题素材检索升级为**混合检索**（向量 + BM25）+ **RRF 融合**
- 查询改写（LLM 把用户问题改写成更适合检索的表述）
- 检索评测：准备 10 组查询-期望块标注，量化 Recall@5 提升

### v1.3 薄弱点智能出题
- 基于 exam_answers 统计各题型/各资料正确率，识别薄弱维度
- 「针对性练习」：一键从薄弱维度组卷；出题时优先检索薄弱相关知识块
- 个人知识掌握度雷达图（做题分析看板增强）

**适合**：想深耕 AI 应用方向、且愿意持续承担 API 成本的求职者。**风险**：演示受限、同质化严重（RAG 项目太多）。

## 5. 方案 C：工程化部署

### v1.1 PostgreSQL + pgvector 一体化
- `DATABASE_URL` 切 PG；pgvector 替代 ChromaDB（SQLAlchemy 已屏蔽差异，主要工作量在迁移脚本 + 向量 SQL）
- alembic 迁移管理（从 `create_all` 升级为版本化迁移）
- 数据迁移脚本（SQLite → PG）

### v1.2 Docker Compose 一键部署
- `docker-compose.yml`：backend + frontend(nginx) + postgres + chroma 四服务
- 一键 `docker compose up` 全栈起；健康检查与依赖顺序
- 生产构建优化（前端 nginx 静态托管 + API 反代）

### v1.3 CI/CD
- GitHub Actions：lint（ruff/eslint）+ 单测 + 构建 + 镜像构建
- PR 模板与分支保护建议；Release 自动化（tag → changelog）

**适合**：简历缺工程化证据的求职者。**注意**：功能增量少，用户可感知度低。

## 6. 方案 D：轻量组合

### v1.1（小版本）
- 错题本（简化版：列表 + 重练，无 SM-2）
- 导出：错题本/题库导出 Anki（TSV）与 Markdown

### v1.2（打磨版）
- 答题卡导航（第 N 题快速跳转、已答/未答标识）
- 考试倒计时（可选时长，到时自动提交）
- 成绩单导出 PDF

**适合**：时间紧张、想快速再拿一个版本迭代记录的场合。

## 7. 通用工程要求（所有方案适用）

1. 每个版本：`pytest` 全绿 + `smoke_test.py` 全绿 + E2E 覆盖新功能主链路
2. 文档同步：设计文档补对应 FR 与 API 契约；README 更新功能清单与验证结果
3. 演示数据：seed.py 同步扩充（如错题本种子数据）
4. 分支策略：`feature/v1.x-xxx` → `develop` → `main`，每个完成版本打 tag
5. 提交规范：conventional commits（feat/fix/chore/docs/test）

## 9. 我的推荐

**方案 A + 决策 2 选"先做 v1.1"**。理由：
- 错题本是你自己练面试题立刻能用的功能，SM-2 是经典算法落地（面试可讲：调度策略、状态机、数据模型）
- 全程不依赖 LLM Key，演示模式完整可跑
- 每个版本独立交付、独立可演示，风险隔离
- 后续若申请到 Key，随时可叠加方案 B 的能力（不互斥）
